# 사이트 운영자를 위한 가이드: 크롤링·하베스터 대응 전략

> 대상: site-harvester 같은 오픈소스 수집 도구로 자사 콘텐츠가 수집될 수 있는 기업·사업자.
> 이 문서는 수집하는 사용자가 아니라 **수집을 당하는 운영자** 관점에서 작성되었습니다.

## 1. 상황 이해

site-harvester와 같은 오픈소스 하베스터는 유료 구독 계정이 이미 보유한 접근 권한 안에서,
사람이 읽는 속도로 콘텐츠를 개인 아카이브로 수집합니다. 캡차 우회·안티봇 회피·페이월 돌파 기능은
의도적으로 없습니다. 즉 여러분이 마주하는 것은 "무단 침입"이 아니라 **정당한 구독자의 개인 백업**입니다.

그럼에도 두 가지 우려는 실재합니다:

- **서버 부하** — 대량 초기 스윕(arbitrarily 큰 아카이브 전체 수집)이 인프라에 부담을 줄 수 있음
- **콘텐츠 유통 통제** — 수집된 텍스트가 재배포될 가능성 (이는 도구가 아닌 이용자의 위반이며, 도구 사용약관도 금지함)

## 2. 전통적 방어: 다층 방어 (Defense-in-Depth)

비즈니스 성격상 기초 방어선이 필요하다면:

| 계층 | 수단 | 효과 |
|------|------|------|
| 법·정책 | 이용약관으로 사전 서면 동의 없는 스크레이핑 금지 명시, robots.txt로 자동화 봇 거부 의사 표명 | 법적 근거 확보, 신의원칙 입증 |
| 아키텍처 | 핵심 데이터를 API 중심(SSR/JSON API)으로 설계, CSS 클래스명 난독화 | 파싱 로직 무력화 — 단, API를 직접 쓰는 하베스터에는 효과 제한적 |
| 인프라 | WAF·안티봇 솔루션으로 비정상 트래픽 차단, 레이트 리밋 | 서버 부하 방어 |

**현실 체크**: 유료 구독자가 자기 계정으로 접근하는 수집은 정상 트래픽과 기술적으로 구분하기 어렵습니다.
API 난독화·봇 지문 감지는 비용 대비 효과가 낮고, 정상 사용자 경험을 해칠 수 있습니다.

## 3. 패러다임 전환: '초격차'와 '오픈'을 통한 해자 구축

콘텐츠 퀄리티와 기획의 해자가 압도적이라면, 무조건 막는 것보다 개방이 유리할 수 있습니다.

| 구분 | 방어 중심 (Closed) | 해자 중심 (Open & Hybrid) |
|------|--------------------|---------------------------|
| 데이터 접근 | 엄격한 차단·숨기기 | 콘텐츠 공개하되 원본 브랜딩 강화 |
| 마케팅 효과 | 제한적 유입 | 크롤링·퍼나르기를 통한 자연스러운 바이럴·유통망 확장 |
| 서버 관리 | 모든 봇 차단 시도 | 비정상 부하만 최소한으로 제어 |

AI와 크롤러의 발전으로 텍스트(Raw Data)는 누구나 복제 가능한 원자재가 되었습니다.
복제되지 않는 것은:

- **안목 (Taste)** — 노이즈 속에서 무엇을 남기고 버릴지 선별하는 큐레이션 역량
- **예측 확실성 (Predictability)** — 불확실한 시장에서 방향을 주는 브랜드 신뢰와 나침반
- **생태계와 멤버십** — 살아 움직이는 오리지널 커뮤니티, 업데이트되는 지속 관계, 원작자와의 접점

긁어가는 것은 과거의 '텍스트 조각(껍데기)'이며, 이것들은 복제할 수 없습니다.

## 4. 실천 지침 (체크리스트)

1. **서버 보호는 최소한으로**: 레이트 리밋 + 비정상 트래픽 대상 WAF만. 정상 구독자 속도의 수집까지 막으려 들지 말 것.
2. **robots.txt·이용약관 정리**: 자동화 수집에 대한 입장 명시. 재배포 금지 조항은 명확히.
3. **원본 브랜딩 강화**: 콘텐츠에 출처·저자·브랜드를 각인 (워터마크, 스타일, 구조 자체가 시그니처).
4. **갱신 가치 설계**: 아카이브 스냅샷은 시간이 지나면 죽는다. 업데이트·인터랙션·커뮤니티로 "계속 오는 이유"를 만들 것.
5. **멤버십 계층 분리**: 텍스트는 개방하되, 큐레이션·예측·접점은 유료 영역에 둘 것.

## 5. 결론

불필요한 크롤링 차단 스트레스에서 벗어나, 인프라 보호를 위한 최소한의 안티봇 장치만 갖춘 뒤
제품 퀄리티와 멤버십 가치에 집중하는 것이 가장 강력하고 지속 가능한 초격차 전략입니다.
